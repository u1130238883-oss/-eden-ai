# 上架 App Store 與收款

這份文件說明兩件事：**怎麼把 App 上架**，以及**錢怎麼進到你手上**。

---

## 一、先講三個不能繞過的限制

### 1. App 內解鎖功能只能用 Apple 內購

App Store 審核規則 3.1.1 規定：在 App 內解鎖數位功能、內容或訂閱，
**必須**使用 Apple 的 In-App Purchase。

不能用微信支付、支付寶、Stripe、PayPal，也不能在 App 裡放連結叫用戶去外面付款。
違反的 App 會被拒審；已上架的會被下架。

所以本專案的會員機制實作為 Apple 的**自動續訂訂閱**，這是唯一能過審的做法。

### 2. Apple 只把收入匯到「銀行帳戶」

在 App Store Connect 的「協議、稅務與銀行業務」中，你必須填寫：

- 一個**銀行帳戶**（收款用）
- 稅務資料（W-8BEN 或當地表格）

**支付寶與微信不是銀行帳戶，Apple 不接受。**

不過你需要的並不是「國際通用信用卡」——那是拿來付款的，不是收款的。
收款只需要一個能收匯款的**銀行帳戶**。若你以中國的身分與地址註冊開發者帳號，
Apple 可以把收入匯到你的中國銀行帳戶。人在義大利不影響註冊，
註冊看的是證件與帳單地址。實際細節請在註冊時向 Apple 確認。

### 3. 上架必須你本人操作

需要 Apple ID 與雙重驗證、開發者帳號、App Store Connect 權限、簽章憑證。
這些都綁定在你的身分上，別人代勞不了。

## 二、上架步驟

### 第 1 步：加入 Apple Developer Program

<https://developer.apple.com/programs/> — 個人身分即可，US$99／年（中國區約 ¥688／年）。
需要有效證件，審核通常一到數個工作天。

### 第 2 步：在 App Store Connect 建立兩個 App

兩個版本是兩個獨立的 App，各建一個：

| | 中英版 | 西義版 |
|---|---|---|
| Bundle ID | `com.ninetwelve.fortune` | `com.ninetwelve.fortune.latin` |
| 名稱 | 九型十二宮 | Nueve y Doce |
| 主要語言 | 繁體中文 | 西班牙文 |

Bundle ID 要先在 <https://developer.apple.com/account/resources/identifiers>
註冊，兩個都要。

### 第 3 步：建立訂閱商品

每個 App 各自建立一個**自動續訂訂閱**，商品編號必須與程式碼一致：

| App | 訂閱商品編號 |
|---|---|
| 中英版 | `com.ninetwelve.fortune.pro.monthly` |
| 西義版 | `com.ninetwelve.fortune.latin.pro.monthly` |

設定：訂閱群組任意命名、期間選 **1 個月**。

**定價**：在價格設定裡選「為各地區自訂價格」，分別設定：

| 地區 | 價格 |
|---|---|
| 歐元區 | €9.99 |
| 美國 | US$9.99 |
| 英國 | £9.99 |
| 中國 | ¥68 或 ¥78（挑最接近 ¥80 的價位點） |

Apple 的價格是從固定價位表挑選，不能填任意數字，所以是 9.99 而不是 10。
其他地區可讓 Apple 依匯率自動換算。

訂閱還需要填：顯示名稱、說明、一張截圖、審核備註。

### 第 4 步：用 Xcode 上傳

```
開啟 ios/NineTwelve.xcodeproj
Signing & Capabilities → Team 選你的開發者帳號
Product → Archive → Distribute App → App Store Connect
```

西義版要在 Archive 前把 Build Settings 改成：

- `SWIFT_ACTIVE_COMPILATION_CONDITIONS` 加上 `LOCALE_LATIN`
- `PRODUCT_BUNDLE_IDENTIFIER` 改為 `com.ninetwelve.fortune.latin`
- `INFOPLIST_KEY_CFBundleDisplayName` 改為 `Nueve y Doce`
- `NINETWELVE_LANGS` 改為 `es it`

（CI 就是用這四個參數建出西義版的，見 `.github/workflows/ios-build.yml`。）

**`NINETWELVE_LANGS` 是什麼**：主畫面上的 App 名稱會跟著手機的系統語言換，
四種語言的名稱都放在專案裡（`ios/NineTwelve/Resources/<語言>.lproj/InfoPlist.strings`），
但一次建置只該收其中兩種 —— 不然西義版裝在中文手機上會顯示「九型十二宮」。
建置時有一個腳本會依這個設定把多餘的語言包刪掉，CI 也會驗證打包後確實只剩該有的兩種。

### 第 5 步：送審

需要準備：App 截圖（各尺寸）、描述、關鍵字、隱私政策網址、支援網址。

**審核時要注意的兩點**：

- **年齡分級**：命理／占卜內容，分級問卷裡有「頻繁／強烈的恐怖主題」等選項，
  據實回答即可，通常落在 12+。
- **中國大陸區**：命理占卜內容在中國區審核較嚴，且中國區上架需要
  ICP 備案。若一開始就卡關，可先不在中國大陸區上架，其他地區照常。

## 三、本機測試訂閱（不用先建商品）

專案內附 `ios/StoreKit/Products.storekit`，可在 Xcode 直接模擬購買：

```
Product → Scheme → Edit Scheme → Run → Options
→ StoreKit Configuration 選 Products.storekit
```

然後執行 App，點命盤／運程／合盤任一頁，就能走完整個購買流程，
不會真的扣款。Debug → StoreKit 選單可以清除交易重測。

## 四、關於「把錢轉到支付寶／微信」

不行 —— 而且問題有兩層：

1. **收費端**：App 內解鎖功能只能走 Apple 內購（見上方第一點）。
2. **付款端**：Apple 只匯款到銀行帳戶，不匯到支付寶或微信。

如果你想繞開 Apple 收費（例如做成網頁版訂閱，讓用戶在瀏覽器付款，
再用帳號登入 App），那是另一套架構，且仍要注意：
iOS App 內不能引導用戶去外部付款，這同樣違反 3.1.1。

最實際的做法仍是：**註冊開發者帳號 → 綁定你的中國銀行帳戶 → 用 Apple 內購收費**。
Apple 會處理全球各地的信用卡、當地支付方式與匯率換算，
每月把扣掉分成（一般 30%，年收入 100 萬美元以下可申請 15%）後的金額匯給你。
